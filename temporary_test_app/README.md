# MOBI 하드웨어 테스트 앱

비콘 2개와 WT901 BLE 센서, 골전도 이어폰을 함께 확인하는 독립 Android 앱입니다.
설치와 실행은 [실행방법.md](실행방법.md)를 참고하세요.

저장소 루트의 `.github`, `mobi-smart-transport-ai`와 같은 위치에 있습니다.
`../mobi-smart-transport-ai/packages/mobile_sensors`를 참조하므로 저장소 전체를 받아야 합니다.
기존 바탕화면 개인 테스트 앱은 그대로 보존했습니다.

- 비콘 A: `C3:00:00:5C:B9:47`, B: `C3:00:00:5C:B9:48`
- WT901BLE68: `F1:35:40:62:CD:43`
- 15초/60초 연속 스캔, RSSI 및 수신 횟수 표시
- WT901 각도 수신과 비콘 동시 스캔
- 수동 Z축 기준에 따른 좌우 소리 및 RSSI에 따른 220~1400ms 소리 간격

RSSI는 정확한 거리나 방향을 뜻하지 않습니다. 방향음은 수동 기준에 대한 센서 회전으로 계산하며 HRTF 기능은 아닙니다.
Passenger 앱이나 서버와의 통합은 별도 작업입니다. 빌드 결과, 로컬 SDK 경로, 키 파일은 커밋하지 않습니다.

프로토콜 참고: https://github.com/WITMOTION/WitBluetooth_BWT901BLE5_0

## 이전 버전 검증 기록

저장소 내 새 위치에서 flutter pub get, flutter analyze, flutter test(13개), Android arm64 debug APK 빌드를 통과했습니다. 비콘/센서 동시 수신 및 골전도 소리는 이전 개인 앱에서 사용자 확인을 받았습니다.

## 개발자 C 담당 기능 및 v1.3.0 변경 이력

안준환의 최신 역할은 개발자 C(Head Tracking / Spatial Audio / 골전도)입니다.

- 센서 Yaw에 시간 기반 저역통과 필터(시정수 80ms)를 적용하고 ±180° 경계를 최단 회전으로 처리합니다.
- 연결 재시작/해제 시 필터와 기준을 초기화하고, 입력이 1초 넘게 끊기면 다음 입력으로 필터를 재설정합니다.
- 기준 방향 대비 수동 목표각에서 머리 Yaw를 빼고 LEFT / FRONT-LEFT / FRONT / FRONT-RIGHT / RIGHT로 나눕니다.
- 정면 구간 ±22.5°, 대각 구간 22.5~67.5°, 좌우 구간 67.5~90°를 사용합니다. 경계 동률은 정면에 가까운 구간입니다.
- 5개 Cue는 고정 스테레오 음량 비율로 출력합니다. 상대각이 ±95°를 벗어나면 후방으로 표시하고 재생을 정지합니다.
- 기존 비콘 RSSI 기반 간격 기능을 유지합니다.

목표각은 수동 테스트 입력이며 Vision/Context/SAL 연결, 위험 Cue 우선순위, HRTF, 현장 방향 식별률/지연 측정은 미완료입니다.
이 버전의 자동 검사와 실기기 확인은 구분합니다. 이전 버전 하드웨어 확인을 새 버전 확인으로 간주하지 않습니다.

v1.3.0 당시 검증: 코드 분석 No issues found, 자동 테스트 16개 통과, Android arm64 debug APK 빌드 성공. 새 버전 실기기 검증은 아직 수행하지 않았으며 커밋/푸시는 하지 않았다.

## v1.3.2 — C・공동 부분의 독립 소프트웨어 구현안

`lib/cue_control.dart`는 Dart 로직이며 Flutter UI/BLE/서버를 참조하지 않습니다. `direction_pan.dart`의 순수 각도 계산을 재사용합니다.
기존 공통 패키지의 비콘 Cue factory/공통 계약은 변경하지 않습니다. 이 파일의 enum은 로컬 실험용이며 합의된 VisionResult/Context API가 아닙니다.

### 입력과 판단 규칙

입력은 전체 객체 목록(snapshot), 현재 상황(waiting/walking/boarding/complete), 머리 Yaw/기준각/반전, 단조 증가한 세션 경과 시간입니다.
객체는 ID, 의미(target/obstacle/irrelevant), 거리 구간(near/medium/far), 기준 좌표계의 목표각(도, 오른쪽 양수), 관측 시각을 가집니다.
목표각과 기준 대비 머리각은 같은 기준 좌표계를 사용해야 합니다. wall-clock/서버 timestamp를 바로 넣지 않습니다.

| 객체/거리 | 대기 | 보행·승차 진행 |
| --- | --- | --- |
| 목표 | 우선순위 1 | 우선순위 1 |
| 가까운 장애물 | 우선순위 2 | 우선순위 3 |
| 중간 거리 장애물 | 무시 | 우선순위 2 |
| 먼 장애물·무관 객체 | 무시 | 무시 |

완료 상태에서는 모든 Cue를 정지합니다. 높은 우선순위가 먼저이며 동률이면 가까운 거리, ID 사전순으로 선택합니다.
이 표는 독립 구현용 초안입니다. 실제 의미/위험도 판단, 거리 구간 산출, AI 추론, Vision 연결은 하지 않습니다.

### 상태와 재생 제어

- 매 tick마다 snapshot에 없는 객체는 해제합니다. 부분 변경 목록으로 사용하지 않습니다.
- 목표 3초/장애물 2초가 지나면 만료합니다. 미래·음수 시각, 비정상 각도는 선택하지 않습니다.
- 객체가 최대 64개를 넘거나 ID가 빈 값/중복이면 현재 출력을 정지합니다. 대기열에 이벤트를 쌓지 않습니다.
- 위험 선택 → 기존 목표 교체 → 위험 해제 시 아직 유효한 목표 복귀. 만료된 목표는 되살리지 않습니다.
- 같은 객체·방향·우선순위는 재시작하지 않습니다. 방향/우선순위만 바뀌면 update합니다.
- 목표가 잠깐 사라졌다가 재등장하면 마지막 시작으로부터 800ms 내 재시작을 억제합니다. 위험은 이 제한을 받지 않습니다.
- cancel/reset 후에는 resume을 명시적으로 호출합니다. reset은 시간 기준/기준각 변경이나 새 세션에 사용하고 반환된 stop을 반드시 출력기에 전달합니다.
- 선택된 객체가 후방(±95° 초과)이면 정지합니다. 후방 위험 대신 목표음을 출력하지 않습니다. 별도의 후방 경고음은 이 초안에 없습니다.
- 반환된 play/update/stop/none 결정은 CueOutputDriver에 순서대로 전달합니다. 출력기는 비동기 작업을 직렬화하며 기존 소리를 중지한 후 새 소리를 시작합니다.
- 처리 중 구형 start가 끝나면 중지하고 최신 결정으로 넘어갑니다. 출력 오류는 호출자에게 전달하고 stop을 시도합니다.
- repeatInterval(위험 500/1000ms, 목표 1500ms)은 출력 어댑터가 적용할 값입니다. 이 제어기는 실제 타이머나 소리를 생성하지 않습니다.
- 센서/이어폰/화면 상태와 단조 시계는 호출자가 관리합니다. 데이터가 새로 안 와도 tick해야 만료가 반영됩니다. 출력 오류 후에는 controller.cancel()을 호출해 명시적으로 재개합니다.

현재 Android 테스트음에 연결된 것은 5방향 히스테리시스(3°)입니다. 새 공동 판단 제어기는 FakeOutput을 통한 독립 테스트만 연결되어 있습니다.
실제 Android 출력 어댑터/위험 효과음/팀원 API는 연결하지 않았습니다.

## v1.4.0 — Cue 제어기와 실제 Android 출력 연결

앞의 v1.3.2에서 FakeOutput에만 연결했던 제어기를 이제 기존 Android 오디오 채널에 연결했습니다.
`native_cue_output.dart`는 CueOutput을 구현하고 DirectionAudioPanel이 실제 WT901 Yaw/기준각을 CueController에 전달합니다.
목표 방향은 기존 수동 선택을 사용하며, 비콘 RSSI는 목표음의 간격 조절에 사용합니다. 비콘의 방위나 장애물 위험을 추정하지 않습니다.

목표음은 700Hz 단일 120ms 소리입니다. 수동 경고음은 1100Hz의 80ms 소리 두 번(시작 간격 160ms), 반복 주기 500ms입니다.
최대 진폭은 기존과 동일하며 시스템 음량을 자동 변경하지 않습니다.
재생 중 '수동 경고 테스트'를 켜면 기준 정면의 수동 경고가 우선 선택되어 기존 소리를 정지하고 경고음을 시작합니다.
해제하면 유효한 목표로 복귀합니다. 경고는 사용자가 켜는 시험 입력이며 실제 위험 감지나 BLE 근접 위험 판단이 아닙니다.
소리 중지/센서 지연/선택 비콘 지연(간격 조절 사용 시)/기준 변경/화면 이탈/출력 오류 시 제어기와 실제 출력을 함께 중지하고 수동 경고를 해제합니다.
최대 30초 제한은 목표/경고 교체 중에도 유지합니다. 이어폰 경로 및 오디오 포커스 상실은 기존 네이티브 정지 처리와 연결되어 있으며 자동 재시작하지 않습니다.
변화 없는 Cue에도 150ms 주기로 출력 상태와 소스 나이를 갱신하므로 watchdog을 유지하면서 중복 start를 하지 않습니다.
재생 시작 처리 중 정지 요청이 오면 큐가 최신 정지를 우선 반영하며 구형 시작 완료 후에도 정지합니다.

이 변경은 임시 앱 범위이며 본 서비스 앱/팀원 API/공동 계약을 수정하지 않습니다.

검증 결과(v1.4.0+9): 코드 분석 No issues found, 자동 테스트 37개 PASS, Android arm64 debug APK 빌드 성공. 네이티브 채널 연결은 mocked channel 테스트와 Android 컴파일로 확인했으며 실제 청취 검증/새 APK 설치는 하지 않았다. 커밋·푸시는 아직 하지 않았다.
