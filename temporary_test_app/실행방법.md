# 임시 앱 실행 방법

## 준비

실제 Android 휴대폰, USB 케이블, 비콘 2개, WT901 BLE 센서, 골전도 이어폰을 준비합니다.
검증에 사용한 도구는 Flutter 3.41.6 / Dart 3.11.4, JDK 21입니다.
Android SDK 36을 사용하며 최소 Android API는 28입니다. 첫 빌드에는 SDK/NDK/CMake 다운로드 공간과 인터넷이 필요할 수 있습니다.
Flutter의 bin을 PATH에 등록하거나 설치 위치의 flutter.bat를 직접 실행하세요.

```powershell
flutter --version
flutter doctor -v
flutter doctor --android-licenses
```

필요한 Android 라이선스 내용을 확인하고 동의합니다. 서버나 .env 설정은 필요하지 않습니다.

## 휴대폰 연결

1. 개발자 옵션에서 USB 디버깅을 켜고 USB로 연결합니다.
2. 잠금을 풀고 이 컴퓨터의 디버깅을 허용합니다.
3. 삼성 자동 차단 기능이 USB 디버깅을 막으면 테스트 동안 해당 설정을 해제합니다.
4. Bluetooth와 위치를 켜고, 센서 제조사 앱에서 센서 연결을 해제합니다.
5. 아래 명령에서 실제 기기 ID를 확인합니다. 에뮬레이터 대신 실기기를 사용하세요.

```powershell
flutter devices
```

## 실행

저장소 루트에서 아래 명령을 실행합니다. DEVICE_ID는 위에서 확인한 ID로 바꾸세요.

```powershell
cd temporary_test_app
flutter pub get
flutter run -d DEVICE_ID --debug
```

상위의 `mobi-smart-transport-ai/packages/mobile_sensors`가 필요하므로 이 폴더만 따로 복사하지 마세요.
앱 ID는 `com.mobi.local.mobi_ble_temp`이며 기존 개인 테스트 앱이 있으면 업데이트됩니다.

APK만 빌드하려면 아래 명령을 사용합니다. arm64 기기용입니다.

```powershell
flutter build apk --debug --target-platform android-arm64
```

결과: `build/app/outputs/flutter-apk/app-debug.apk`. APK와 build 폴더는 Git에 올리지 않습니다.

## 비콘과 센서 확인

1. 앱의 주변 기기와 정확한 위치 권한을 허용합니다.
2. 센서를 연결하고 각도 및 수신 횟수가 계속 바뀌는지 봅니다.
3. 15초 또는 60초 스캔을 시작해 A/B의 RSSI와 수신 횟수를 확인합니다.
4. 센서 연결 상태에서도 스캔할 수 있습니다. 스캔 종료 후에도 센서 수신이 유지됩니다.

| 장치 | MAC |
| --- | --- |
| 비콘 A | C3:00:00:5C:B9:47 |
| 비콘 B | C3:00:00:5C:B9:48 |
| WT901BLE68 | F1:35:40:62:CD:43 |

다른 장치를 쓰면 lib/main.dart의 비콘 정보, lib/continuous_beacon_scanner.dart의 MAC 필터, lib/wit_sensor_panel.dart의 센서 MAC을 함께 확인하세요.

## 골전도 소리 확인

1. 이어폰을 연결하고 미디어 볼륨을 낮게 시작합니다.
2. 센서를 원하는 기준 방향으로 두고 Z축 기준을 설정합니다.
3. A/B 중 대상을 선택하고 60초 스캔을 시작합니다.
4. 소리 패널에서 재생하고 센서를 돌려 좌우 소리를 확인합니다. 반대로 들리면 반전 옵션을 사용합니다.
5. 비콘에 가까워져 RSSI가 강해지면 소리 간격이 짧아집니다.

간격은 RSSI -45dBm에서 약 0.22초, -65dBm에서 약 0.81초, -85dBm에서 약 1.4초입니다.
실제 미터 거리와 일대일 대응하지 않습니다. 비콘 연동을 끄면 고정 1초 간격으로 확인할 수 있습니다.
앞뒤 구분이나 비콘의 실제 방위를 계산하는 기능은 아닙니다.

수동 정지 또는 최대 30초 후 정지합니다. 기준/대상 변경, 수신 지연, 연결 해제, 오디오 경로/포커스 변경, 앱 비활성 상태에서도 정지하도록 구현했습니다.
이러한 모든 예외 상황의 실기기 검증이 완료되었다는 의미는 아닙니다. 다시 재생하려면 직접 시작합니다.

## 검사와 종료

```powershell
flutter analyze
flutter test
```

확인이 끝나면 소리와 스캔, 센서 연결을 종료합니다. flutter run 터미널에서는 q로 종료합니다.
필요하면 USB 디버깅과 자동 차단 설정을 원래 상태로 되돌립니다.

기기가 보이지 않으면 케이블, 잠금 해제, USB 디버깅 허용 상태를 확인합니다.
센서가 연결되지 않으면 제조사 앱 등 다른 연결을 해제하세요. 좌우 차이가 없으면 휴대폰의 모노 오디오 설정도 확인합니다.
Windows 한글 경로 검사를 위한 android.overridePathCheck 설정이 포함되어 있습니다.
네이티브 도구에서 한글 경로 오류가 계속 나면 저장소 전체를 영문 경로에 받아 같은 명령으로 실행하세요.
android/local.properties는 각 PC에서 생성하는 파일이며 공유하지 않습니다.

## v1.3.0: 개발자 C의 Yaw 필터와 5방향 Cue

기존 실행 명령을 그대로 사용합니다. 연결 후 필터 Yaw 표시가 갱신되면 정면을 보고 기준각 버튼을 누르세요.
센서는 머리와 함께 움직이도록 장착해야 머리 회전 입력으로 확인할 수 있습니다. 장착 축과 좌우 부호를 먼저 확인합니다.

1. 비콘 없이 방향만 확인하려면 비콘 간격 조절을 끕니다.
2. 수동 목표 선택에서 왼쪽/왼쪽 앞/정면/오른쪽 앞/오른쪽을 선택합니다.
3. 방향음을 시작하고 출력 Cue 및 좌우 음량 변화를 확인합니다.
4. 소리를 멈춘 뒤 다른 목표를 선택합니다. 목표각은 기준 방향에 대한 각도입니다.
5. 머리를 돌리면 상대각 = 목표각 - 기준 대비 머리 Yaw로 보정됩니다.
6. 목표가 머리 기준 뒤쪽(±95° 밖)이 되면 정지합니다. 다시 앞쪽으로 돌아와 직접 재생하세요.

필터 시정수는 80ms이며 실제 종단 출력 지연을 측정한 값은 아닙니다.
5방향 표시는 스테레오 비율로 표현하며 사용자의 실제 방향 구별 능력은 별도 확인 대상입니다.
실제 Vision 입력이나 위험도 우선순위는 아직 연결하지 않았습니다.

### v1.3.1 경계 수정
좌우 ±90° 선택 시 기준각의 작은 흔들림으로 시작 버튼이 비활성화되는 문제를 수정했습니다. 좌우 끝에 5° 허용 범위를 두고, 상대각 ±95° 초과 시 정지합니다.

## v1.3.2 하드웨어 없는 소프트웨어 확인

USB와 센서 없이 `flutter test test/cue_control_test.dart`로 공동 판단/출력 제어 시나리오를 실행할 수 있습니다.
전체 검사는 `flutter test`, 코드 분석은 `flutter analyze`입니다. 판단 규칙과 입력 예제는 README의 v1.3.2 절을 참고하세요.
이 제어기의 위험 이벤트는 테스트용 가짜 입력이며 현재 앱에서 실제 위험 경고음을 재생하지 않습니다.
현재 앱의 5방향 출력에는 경계 전환을 줄이는 3° 허용 구간이 적용됩니다.
