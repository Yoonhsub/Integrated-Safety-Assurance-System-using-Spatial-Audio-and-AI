## Android 에뮬레이터 결과와 미해결 사항

기존 API36 x86_64 AVD를 원본 초기화 없이 read-only/no-snapshot 방식으로 실행했다. 후보 APK 설치는 성공했고 MainActivity 시작을 요청했다. 그러나 앱보다 먼저 SystemUI·키보드·전화 등의 ANR이 발생했으며 앱에서도 Input dispatching timeout이 발생했다. 앱 ANR 당시 load44.4와 자원 압박이 관찰됐다.

두 차례 기다려도 정상 UI를 검증하지 못했다. 환경 자원 압박과 앱 결함의 원인을 분리할 근거가 부족하므로 로그인 화면·탐색 PASS로 기록하지 않는다. 추가 메모리 조회가 권한 검토에서 거절되어 우회하지 않았으며 RAM 확대·보안 설정 변경·AVD 초기화를 하지 않았다. 에뮬레이터를 종료하고 연결 장치가 남지 않음을 확인했다. 네트워크 proxy가 적용되지 않았고 요청한 emulator 제한 옵션의 완전한 격리를 독립 검증하지 못했으므로 Android 실행을 완전 네트워크 격리로 주장하지 않는다.

낮은 부하의 기존 로그인·홈 widget 테스트9개를 다시 실행해 모두 통과했으나 Android 런타임 문제를 해결했다는 의미는 아니다.

## TAGO 별도 진단 추가

이 절은 위 WT 후보 이후의 후속 작업이다. 일반 노선 검색과 분리된 TAGO 테스트 버튼 및 인증된 읽기 전용 Backend 경로를 추가했다. 기존880개 소스 파일과 Git 차이를 별도 복사·해시 검증한 뒤 작업했다.

- 도시코드·정류장 ID로 도착 조회, 도시코드·노선 ID로 마지막 보고 정류장 조회를 수행하는 로컬 endpoint2개를 추가했다. 상세 계약은 [TAGO 진단 안내](TAGO_DIAGNOSTICS.md)를 참조한다.
- health는 연결만 확인한다. TAGO 성공·빈 결과·서비스키 없음·공급자 오류·401/403·구버전404를 구분한다. mock/cache fallback을 하지 않고 원본 관측시각이 없으면 null을 유지한다.
- 앱 입력과 결과를 분리하고 긴 메타데이터·레코드는 상세 보기로 옮겼다. 자동 요청 없이 사용자가 누른 검사만 실행하며, 새 경로는 모든 플랫폼에서 승객 인증이 필요하다.
- API는 기존 역할 범위 안에 새 읽기 경로만 허용한다. 원격 서버·서비스키·트래픽을 변경하지 않았고 실제 TAGO 호출은 수행하지 않았다. 기존 배포 서버에 새 API가 없으면 미지원으로 표시된다.
