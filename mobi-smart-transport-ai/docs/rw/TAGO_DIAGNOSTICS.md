# TAGO 실데이터 진단

이 기능은 일반 노선 검색과 분리된 수동·읽기 전용 검사다. 기존 로그인 계정으로 인증한 뒤 홈의 **TAGO 실데이터 테스트**를 연다. 앱에 서비스 키를 입력하지 않는다.

## 앱 사용

1. 상단의 설정된 Backend 주소가 검사하려는 서버인지 확인한다. 앱에서 다른 주소로 토큰을 보내도록 주소를 편집할 수 없다.
2. `서버 상태 조회`는 `/health` 연결만 검사한다. 인증 또는 TAGO 데이터 성공을 의미하지 않는다.
3. 실제 TAGO 도시코드와 정류장 ID를 입력하고 `도착 조회`를 누른다. 버스 번호 대신 정류장 nodeId가 필요하다.
4. 실제 도시코드와 노선 routeId를 입력하고 `위치 조회`를 누른다. 이 결과는 마지막 보고 정류장으로, GPS·실제 현재 위치·버스 접근의 증명이 아니다.
5. 입력과 결과는 두 화면으로 분리되며 상세 메타데이터와 레코드는 `응답 상세 보기`에서 확인한다. 자동 조회는 하지 않는다.

사용자가 확인하지 않은 ID를 자동 입력하거나 가짜 예시로 성공을 보여주지 않는다. 0건은 버스가 없거나 운행이 끝났다는 증거가 아니다. MOCK/CACHE 대체 자료는 실데이터 성공으로 취급하지 않는다.

## 추가 Backend 계약

- `GET /diagnostics/tago/arrivals?cityCode=...&stopId=...`
- `GET /diagnostics/tago/locations?cityCode=...&routeId=...`
- 기존 인증 경계를 사용하며 passenger/driver/admin 역할의 읽기 요청만 허용한다. 기존 API 정책을 넓히지 않는다.
- 도시코드는 숫자1~6자리, ID는 영문·숫자·밑줄·하이픈1~64자리다.
- 공식 TAGO 호스트와 고정 endpoint만 사용한다. 서버의 기존 서비스 키 설정을 이용하며 응답·로그에 키를 출력하지 않는다.
- 기존 앱 MOCK 모드와 독립적으로 실 API를 조회하고 cache/mock으로 대체하지 않는다. 키 없음·시간초과·공급자거절·응답형식 오류를 별도 코드로 반환한다.
- source는 PUBLIC_API 또는 ERROR, status는 SUCCESS/EMPTY/ERROR, fallbackUsed는 false다. 앱도 provider·출처·질의 ID·레코드 모양을 검증한다.
- fetchedAt은 서버 조회 시각이고 observedAt은 현재 계약에서 null이다. 제공되지 않는 원본 관측시각을 만들어내지 않는다. 앱 수신시각 역시 실제 최신성의 증거가 아니다.
- 위치 레코드 positionType은 LAST_REPORTED_STOP이며 좌표를 GPS로 반환하지 않는다.
- 최대100건의 첫 페이지를 조회한다. 전체건수와 일부결과 여부를 표시한다.

## 배포·검증의 경계

진단 API는 로컬 소스에 추가한 것이며 이 작업에서 배포하지 않았다. 기존 운영 서버에 endpoint가 없으면 HTTP404를 **현재 서버에서 지원하지 않는 조회**로 표시한다. 앱만 업데이트해서 새 서버 기능이 생기는 것은 아니다.

실제 TAGO 요청, 실사용자 인증 및 운행 데이터 확인은 아직 수행하지 않았다. fixture 테스트와 APK 빌드 성공을 실제 TAGO 성공으로 보고하지 않는다. 새로운 Backend 배포 및 트래픽 변경은 소스·환경·검증·복구 범위를 정해 별도로 진행해야 한다.
