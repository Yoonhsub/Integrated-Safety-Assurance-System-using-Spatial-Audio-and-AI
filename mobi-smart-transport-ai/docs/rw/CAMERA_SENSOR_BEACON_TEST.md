# 카메라·머리 WT901·비콘 통합 방향 시험

## 범위

머리에는 WT901, 휴대폰 후면 카메라는 손에 드는 배치용 로컬 진단이다. 휴대폰 rotation-vector로 후면 카메라 광축의 수평 방향을 추가 측정한다. 비콘은 선택한 A/B의 실측 평활 RSSI로 반복 간격만 정한다. 카메라의 단일 bus를 수동으로 목표 비콘에 연결한다. 유효한 단일 bus_door가 있으면 문을 우선 사용하고 없으면 bus 중심을 사용한다. 차량 인증·위험 판정·실제 탑승 안내가 아니다. 이전의 RSSI 기반 좌→정면→우 가정은 이 화면에서 사용하지 않는다.

계산은 `촬영 시점 카메라 수평 방향 변화 + bbox 광선 각도 - 현재 머리 회전 변화`다. 머리와 카메라를 같은 표식에 맞춰 각자 초기 영점을 잡는다. 카메라 광선은 pinhole 근사 atan((2*cx-1)*tan(FOV/2))를 사용한다. 휴대폰 방향은 촬영 시각에 250ms 이내인 샘플만 사용한다. 축과 WT901 회전 부호는 실제 장착 후 확인해야 한다. 수평 화각은 Camera2의 렌즈 초점거리·센서 물리 크기·현재 프레임 크기/회전으로 자동 근사한다. 중심 크롭·기본 줌을 가정하며 실제 활성 크롭/EIS·렌즈 보정의 정확도 검증은 별도다. 정보 누락·초점거리 복수 후보이면 임의 화각 없이 중지한다. 수평을 유지하고 촬영한다. 자기장·회전 센서 드리프트 영향으로 실험 중 기준을 재확인한다.

## 실행

1. 기기 점검 → **카메라·센서·비콘 통합 방향 시험**.
2. 이어폰 연결. 비콘 A를 문 역할 표식에 고정하고 B는 끈다. 권한 허용 → 버스 탐색 시작(5분). 목표 A 선택.
3. 아래 카메라 영역에서 카메라 시작과 권한 허용을 먼저 완료한다. 카메라 권한 창이 뜨면 앱 비활성화 처리가 일어나므로 기준 설정은 그 후 진행한다.
4. WT901 센서 연결 → 머리를 정면으로 두고 도로 정면을 기준으로 설정.
5. 휴대폰 방향은 화면 진입·복귀 시 자동 측정한다. 휴대폰을 세우고 후면 카메라가 같은 정면 표식을 보게 한다. 휴대폰 방향 수신 중인지 확인한다.
6. 카메라 정보 자동 적용 완료 상태를 확인한다. 화각 입력 칸은 없으며 기본 줌의 근사 방향 시험으로 기록한다.
7. 화면의 단일 문을 선택 비콘 시험 대상으로 수동 연결 체크. 여러 버스·문이 있으면 시험하지 않는다.
8. 머리·카메라 동일 정면 설정. 촬영 시점의 최신 자세와 단일 문이 잡히면 버스 소리 시작 활성화. 필요시 센서 회전 부호 반대로 설정 후 기준 재설정.
9. 새 입력으로 수신이 복구돼도 소리는 수동 시작한다. 중단 원인 문구 확인.

## 단일 출력·중단 조건

카메라 검출 한 프레임당 단일 버스만 사용한다(bus confidence >=.5, door >=.55, 문 면적 70% 이상이 bus 박스 안). 여러 bus 또는 bus 미검출이면 이전 방향을 즉시 지운다. 문 미검출·여러 문은 bus 중심으로 되돌리며 문 위치 안내로 표시하지 않는다. 후면 카메라 전용. 방향 계산에는 카메라 관찰 1초·휴대폰 방향 300ms·머리 센서 1초 이내의 값이 필요하다. 기본 중앙 근접음에는 목표 비콘의 실제 3초 이내 신호만 필요하다. 방향 입력이 없으면 비프음 자체를 끄지 않고 중앙으로 전환한다. 센서 재보정·연결 상실·화면 이탈 시 방향 기준을 무효화한다. 머리 센서 상실만으로 기본 중앙 근접음을 끄지는 않는다. 네이티브 이어폰 출력 제한·watchdog·5분 종료는 기존 경로를 재사용한다. 후방 목표는 기존 수정에 따라 방향 없는 중앙 근접음이다. 실제 장애물 경고 우선순위 시연은 이번 문 추적 시험에 포함하지 않는다.

손의 카메라와 머리(귀)의 위치 차이는 측정하지 않으므로 근거리 시차 오차가 있다. 현재 수평 방향+5단계 패닝 시험이며 실제 공간 위치나 3D 음원 위치를 보장하지 않는다. 촬영 해상도·화각 변경, 센서 이동·장착 변경 시 기준을 다시 맞춘다. 여러 버스 중 실제 목표 차량을 자동 식별하지 않는다.


휴대폰 방향 시작 버튼은 제거했다. 화면 이탈 시 측정을 해제하고 복귀 시 자동 구독하지만, 기준과 음향은 자동 복구하지 않는다. 센서 재보정·비콘 선택 변경은 휴대폰 방위 측정 구독을 끊지 않는다.

정면 기준 저장은 버스·문 검출, 비콘 수신, 수동 대상 연결, 화각 취득과 독립적으로 수행한다. 최신 머리 센서·휴대폰 방향만 필요하다. 설정 완료 상태를 별도로 표시하며, 음향 시작은 기존의 전체 입력 조건을 그대로 요구한다. 대상 선택·비콘 스캔 변경은 방향 영점을 지우지 않고 추적 대상만 초기화한다. 카메라 렌즈/영상 회전 변경이나 센서 기준 변경은 재보정이 필요하다.


통합 시험 화면의 버스 소리 시작은 문 미검출 상태에서도 대기를 시작한다. 대기 중 전체 입력이 최신이고 문이 확인되면 재생한다. 재생 중 문을 놓치되 머리 센서·목표 비콘은 유효한 경우에는 무음 대기를 유지하고 새 문 확인 후 재생한다. STOP·화면 이탈·목표/세션 변경·실제 재생 중 머리 센서/비콘 상실은 대기를 취소한다. 대기·재생 합계 5분 제한. 초기 정면 보정과 수동 대상 연결은 여전히 필요하며 시작 버튼이 이를 대신하지 않는다.

## BLE/오디오 갱신 공백 개선 및 버스 중심 대체

로그에서는 음향 구간에 A 수신 공백 5~6초가 있었으나 그때 BLE stopScan 호출은 없었다. 문 검출 변화마다 AudioTrack·오디오 포커스를 해제/재생성하는 경로를 확인했다. 이것이 전파 공백의 유일한 원인이라고 단정하지 않는다. 시각 목표만 놓쳤고 머리 센서·목표 비콘은 최신이면 기존 출력 경로를 0/0 음량으로 유지하고 150ms마다 실제 입력 age를 갱신한다. 재검출 시 같은 AudioTrack을 update로 재사용한다. 네이티브의 동일 음량 반복 설정을 줄였다. 비콘/센서 만료·이어폰 연결 해제·STOP·화면 이탈·5분 만료는 실제 stop/release를 유지한다. 3초 비콘 만료 기준을 완화하거나 마지막 RSSI를 새 수신처럼 갱신하지 않는다.

MOBI_AUDIO_STATE 로그에 event, sensorAgeMs/sensorReady, beaconAgeMs/beaconFresh, targetReady, reference, scope, message를 남긴다. 네이티브 MobiTone 시작·정지 사유와 카메라 클래스/confidence도 남긴다. 실제 무선 수신 안정화 성공 여부는 업데이트 후 장비 배치를 고정해 별도 재시험해야 한다.

## RSSI 기본음 우선 정책과 스캔 정체 복구

시작 버튼은 실제 목표 비콘 RSSI가 있으면 카메라·머리 센서·보정 유무와 무관하게 중앙 근접음을 재생한다. 카메라/휴대폰/머리 정보가 모두 유효할 때만 방향을 반영한다. 네이티브 sensorRequired=false 경로는 최신 비콘(0~2999ms), 좌우 균형 출력, HRTF 없음 조건에서만 허용한다. 기본음과 방향음 사이의 전환은 동일 트랙 update이며 재연결하지 않는다.

ContinuousBeaconScanner는 알려진 E2 비콘용 legacy 광고·lowLatency 설정을 사용한다. 목표 패킷 갱신이 2초 정체되면 최대 30초에 1회 스캔 재시도를 수행하며 원 스캔 만료 시각을 연장하지 않는다. 재시도 자체가 RSSI/lastSeen을 갱신하지 않는다. 실제 3초 신호 상실 시 출력 중지는 유지한다. 기존 오디오 경로 재사용 수정만으로는 20:30:21 beaconAgeMs=3063 만료를 해결하지 못했음을 실측 로그로 확인했다. 이번 스캔 설정/재시도 및 기본음 분리 후 재시험은 별도로 기록한다.
