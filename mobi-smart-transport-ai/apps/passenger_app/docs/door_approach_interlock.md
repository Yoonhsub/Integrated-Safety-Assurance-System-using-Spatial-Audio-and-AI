# 탑승문 접근 안내 중단 조건 — 11월 15일 시연 준비

현재 단계는 **공통 중단 상태 모델 + 모의 입력 웹 재생 화면**이다. 실제 BLE, AI 탐지, 서버 판정, 머리 추적은 이 화면에 연결하지 않았다. 기존 하드웨어 진단과 별도로 실행하며 모든 입력을 모의로 표시한다. 실제 탑승 가능 여부나 문 열림/발밑 안전을 판단하지 않는다.

## 동작

- 선택된 문 ID의 새 관측만 받는다. 다른 ID·중복·역순·미래·기한이 지난 관측은 유효 시각을 갱신하지 않는다.
- 목표 비콘 관측이 3초 이상 오래되면 접근 안내를 끊고 “탑승 위치를 다시 확인해 주세요”를 안내한다. 새 콜백이 없어도 100ms 주기 tick에서 검사한다.
- 위험 정보도 신선한 전체 스냅샷이 있어야 한다. 위험도 순으로 하나를 선택하고, 동률은 ID 순으로 결정한다. 방향 불명은 중앙 스테레오 경고로 전달한다. 현재는 주의도 보수적으로 접근 안내보다 우선한다.
- 위험 관측이 만료되는 것을 장애물이 사라졌다고 해석하지 않는다. 위험 스냅샷이 2초 이상 오래되거나 잘못된 입력이면 주변 정보 확인 상태에서 안내를 멈춘다.
- 명시적인 새 위험 해제 스냅샷을 받은 뒤에도 **그 해제 시점 이후의 목표 비콘 관측**을 받을 때까지 재개하지 않는다. 경고 도중 받았던 비콘 값만으로 재개하지 않는다.
- 기존 `SpatialVerificationEngine`/`SpeechPriorityCoordinator`/웹 스테레오 출력으로 정지 확인 후 다음 cue/음성을 시작한다. 이전 비동기 재생 준비가 늦게 끝나도 당시 요청의 유효성을 다시 검사한다.
- STOP, 화면 비활성화, 출력 정지 확인 실패에서 새 안내를 차단한다. 출력 실패 후에는 페이지를 다시 열어야 한다. 화면 복귀로 입력 모의 재생이나 안내를 자동 시작하지 않는다.
- 가까움에서는 “탑승 위치 근처입니다. 문과 발밑을 확인해 주세요”까지 안내한다. 도착 상태는 신선한 가까움 상태에서 시연자가 확인 버튼을 눌렀을 때만 바뀐다.

3초/2초는 현재 시험 기본값이며 실측으로 보정한 현장 수치가 아니다. 모든 모델 시각은 같은 세션의 단조 증가 경과 시간이다. 실제 수집기를 연결할 때 wall-clock/서버 수신 시각을 그대로 섞거나 관측 시각을 tick마다 새로 만들면 안 된다.

## 실행

Flutter가 PATH에 있는 PowerShell에서 프로젝트 루트(`mobi-smart-transport-ai`)를 기준으로 실행한다. 출력 경로는 저장소 밖의 아직 없는 폴더를 지정한다.

```powershell
./scripts/build_local_spatial_verification.ps1 -DoorApproach -OutputPath C:/mobi-door-demo
python -m http.server 5280 --bind 127.0.0.1 --directory C:/mobi-door-demo
```

PC 브라우저에서 `http://127.0.0.1:5280`을 직접 연다. `-DoorApproach`와 `-GuidanceRuntime`은 함께 사용할 수 없다. `MOBI_LOCAL_DOOR_APPROACH=true`를 명시한 localhost debug 진입점만 허용한다. 이 진입점은 Android Gradle 진입점 허용 목록에 추가하지 않았다. 빌드 스크립트는 기존 웹 오디오 graph와 로컬 한글 폰트를 재사용한다. 자동 재생은 없다.

## 모의 리허설

1. “새 장애물 전체 스냅샷 모의 재생”과 “새 목표 비콘 관측 모의 재생”을 켜고 안내를 시작한다. 위험도 none에서 접근 상태를 확인한다.
2. 위험도를 danger로 바꾸고 방향을 좌/우/불명으로 바꿔 경고와 접근 음성 중단을 확인한다. 불명 방향은 중앙이다.
3. 경고 중 목표 관측 재생을 끈 뒤 위험도를 none으로 바꾼다. 새 목표 관측을 기다리는 상태로 남는지 확인한다. 목표 관측 재생을 켜 새 관측이 들어온 뒤에만 재개해야 한다.
4. 접근 중 목표 관측 재생을 끈다. 3초 후 안내 중단과 탑승 위치 재확인 문장을 확인한다. 위험 스냅샷 재생을 끄면 2초 후 주변 정보 재확인 상태가 된다.
5. 목표 관측을 복구하고 가까움 구간을 켠다. 문과 발밑 확인 요청을 확인한 뒤 “시연자 도착 확인”을 누른다. 가까움만으로 도착 상태가 되면 안 된다.

## 검증 경계와 다음 연결

`door_approach_guard_test.dart`는 시각·입력 만료·우선순위·재개 조건·수동 완료를 검사한다. `door_approach_demo_test.dart`는 가짜 오디오 출력에서 기존 접근 음성이 경고로 교체되는지, 늦은 준비 완료가 STOP을 무시하지 않는지, 출력 중지 실패 후 새 재생이 차단되는지 검사한다. 자동 검사와 실제 청취 통과는 다르다.

다음 작업은 기존 스캐너의 평활화된 실측 근접 구간과 실제 AI 또는 기록 탐지 이벤트를 이 상태 모델에 연결하는 것이다. 화면의 모의 재생 타이머는 수집기로 사용하지 않는다. 기존 `ObstacleCueSnapshot`은 도로 기준 각도를 요구하지만 이번 모델은 **화면 기준 스테레오 pan**을 받으므로 두 좌표계를 임의로 바꾸지 않는다. 위험도 없는 탐지에서 임의의 실측 위험도를 만들어 넣지 않는다. 실제 producer가 위험도를 제공하지 못하면 명시적 시험 위험 입력으로 기록한다.
