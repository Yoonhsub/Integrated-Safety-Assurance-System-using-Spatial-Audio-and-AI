# 이어폰 연결 상실 후 스피커 재생 방지

## 발견된 문제

카메라 시연 버전 `6fb0970`에서 이어폰 전원을 끄면 담당자는 소리 중단을 보고했지만 화면은 `near`에 머물렀다. 이어폰을 꺼둔 채 새 모의 danger를 넣자 휴대폰 스피커에서 경고가 들렸다. 2026-11-11 20:59:33 KST 로그에도 RIGHT cue 시작·완료가 있다. 따라서 단순한 ‘소리 멈춤’ 관찰은 앱의 연결 상실 감지·새 출력 차단 성공을 뜻하지 않았다. 해당 항목은 실패이며 수정판의 실기기 재시험과 분리한다.

## 변경

- Android `LocalStereoCue`가 `AudioDeviceCallback`으로 이어폰 출력 장치 추가·제거를 전달하고 연결 상태 조회를 제공한다. 새 탑승문 시연만 `headphonesOnly`를 요구한다. 기존 수동 오디오 진단의 스피커 시험 기능은 유지한다.
- 지원 연결은 Bluetooth A2DP/BLE headset, 유선 headset/headphones, USB headset이다. 일반 스피커와 Bluetooth 통화 전용 SCO는 미디어 스테레오 이어폰으로 인정하지 않는다.
- `HeadphoneAudioGate`는 사용자의 안내 시작 때 연결을 확인해야 출력이 허용된다. cue/TTS 준비와 실제 시작 직전에도 다시 확인한다. 조회 실패·늦은 성공 응답·연결 상실은 새 출력을 허용하지 않는다.
- 연결 상실 시 활성 cue와 TTS를 중지하고 페이지를 disarm한다. BLE 스캔과 모의/카메라 입력도 중지한다. 재연결 이벤트는 출력 허용 상태를 복구하지 않으며 사용자가 스캔·입력·안내를 다시 시작해야 한다.
- 이어폰이 없는 최초 시작은 안내를 중지한 채 연결 필요 문구를 표시한다. 연결 뒤 사용자가 다시 안내 시작을 누를 수 있다. 출력 정지 확인에 실패하면 새로운 재생 허용을 막는다.
- 네이티브 prepare/play도 이어폰 필수 소유자에 대해서는 연결 상태를 재검사한다. 연결된 이어폰 하나가 제거되면 다른 출력 장치가 있어도 보수적으로 중지한다.

연결 목록은 실제 TTS 출력 경로 계측이 아니다. OS에서 이어폰을 연결한 채 수동으로 스피커를 선택하는 경우까지 이 변경으로 검증됐다고 표시하지 않는다. Android 장치 제거 이벤트 전달과 TTS 취소는 비동기이며, 무음 전환의 정확한 지연·음향 파형은 별도 계측 대상이다. 이번 실기기 완료 기준은 이어폰 OFF 상태의 새 출력 차단, 연결 상실 시 중지 상태 전환, 재연결만으로 자동 출력하지 않음이다.

## 재시험

1. 이어폰을 꺼둔 상태에서 새 시연 화면의 BLE 스캔과 모의 위험 해제 입력을 준비한다. 안내 시작을 누른다. 연결 필요 문구와 stopped를 확인하고 스피커에서 출력이 없어야 한다.
2. 이어폰을 미디어 오디오로 재연결한다. 연결만으로 소리가 나지 않아야 한다. 사용자가 안내 시작을 누르면 새 목표 관측 후 근접 음성을 들을 수 있어야 한다.
3. 실제 음성이 진행 중일 때 이어폰을 끈다. `HEADPHONE_STATE available=false`, 페이지 stopped, 출력 정지 확인을 기록한다. 휴대폰 스피커로 계속 들리는지도 담당자 관찰로 별도 기록한다.
4. 다시 연결해 자동 출력이 없는지 확인하고 필요한 입력과 안내를 수동으로 시작한다.
