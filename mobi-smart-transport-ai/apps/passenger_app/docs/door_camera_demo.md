# 카메라 탐지 → 탑승문 안내 중단 시연

## 이번 변경의 범위

Android debug의 **탑승문 접근·중단 시연 (실측 BLE)**에 기존 후면 카메라·번들 통합 v4 모델을 연결했다. `LocalVisionPage`/`VisionWorker`/`FramePump`를 재사용하며, 서버에 프레임·판정 요청을 보내지 않는다. 기존 독립 카메라 화면과 온라인 Guidance의 정책은 바꾸지 않는다.

AI 출력은 `classId/confidence/bbox`이며 충돌 위험도를 포함하지 않는다. 기존 Python `SafetyInterpreter`도 단일 프레임으로 판단할 수 없는 위험을 확정하지 않는다. 따라서 새 `DoorVisionPolicy`는 명시적으로 켠 시연에서만 다음 **규칙 기반 주의**를 부여한다. 실측 탐지와 위험도 규칙을 따로 표시한다.

| 입력 | 처리 |
|---|---|
| parked_pm / pole / tree_trunk, 기존 unifiedV4Thresholds 이상 | 화면 bbox 중앙의 좌·중앙·우로 주의 경고 |
| bus / bus_door / bus_stop | 정보성 탐지, 장애물 위험으로 변환하지 않음 |
| 정상 빈 탐지 전체 스냅샷 | 이번 프레임에 지원 장애물 미검출. 경로 안전 확인이라는 뜻이 아님 |
| 알 수 없는 클래스·기준 미달 신뢰도·오류·잘못된 데이터 | 위험 정보 불명으로 접근 보류 |
| bbox 방향 누락 | 중앙 경고 |
| 카메라 중지·관측 2초 만료 | 기존 경고/접근 출력을 중지하고 주변 정보 재확인 |

박스 크기와 신뢰도를 거리·충돌 위험도·문 열림·발밑 안전으로 바꾸지 않는다. 모든 카메라 장애물은 `caution`이며 실제 `danger` 산출 기능은 없다. 모의/기록 `danger` 우선 재생은 기존 경로로 별도 시험한다. 여러 장애물이면 기존 Guard가 가장 높은 위험도 하나를 선택하고 동률은 ID 순이다. 이 시연 규칙에는 경로 추정·객체 추적·HRTF·머리 회전 보정이 없다.

## 데이터와 중단 처리

- `LocalVisionPage.sessionNow`를 선택적으로 주입해 FramePump·카메라 capture·Door Guard가 같은 단조 시계를 사용한다. 원본 host 카메라 콜백 시각을 유지하며 UI tick/전송 시각으로 갱신하지 않는다. 센서 노출 시각을 측정한 것은 아니다.
- 중복 프레임 ID, 역순·미래·2초 이상 지난 관측을 거부한다. 카메라 stop은 `onInputUnavailable`을 통해 비동기 카메라 정리 전에 Guard를 무효화한다.
- 실제 카메라 규칙과 모의 연속 스냅샷/JSON 재생은 동시에 켤 수 없다. 입력원을 바꿀 때 기존 위험 정보를 무효화하며 새 프레임과 새 목표 비콘을 요구한다. 폐기된 카메라의 늦은 콜백은 무시한다.
- 장애물 경고는 기존 `SpatialVerificationEngine`/`SpeechPriorityCoordinator`를 사용한다. 접근 TTS를 중지하고 정지 확인 뒤 좌우 stereo cue와 주의 문장을 출력한다. 경고 해제 뒤에도 해제 이후 새 목표 관측이 있어야 접근 안내를 재개한다.
- STOP·Bluetooth 중단·스캔 종료·화면 이탈은 기존과 같이 안내를 정지하고 카메라 입력도 해제한다. 복구만으로 자동 재생하지 않는다.

## 실행과 담당자 재시험

프로젝트의 `apps/passenger_app`에서 `flutter build apk --debug --no-pub --target lib/main.dart`로 빌드한다. 패키지는 기존 앱과 분리된 `com.example.mobi_passenger_app.handoff`이다. 업데이트할 때 기존 원본 패키지를 삭제하지 않는다.

1. 통제된 장소에서 이어폰을 휴대폰 미디어 출력으로 연결하고 음량을 낮춘다. 비콘 A 전원을 켠다.
2. **이어폰·BLE 기기 점검 → 탑승문 접근·중단 시연 (실측 BLE)**을 연다. **실측 BLE 스캔 시작 (5분)**을 눌러 A 식별자·관측 시각·평활 RSSI 갱신을 확인한다.
3. **실측 카메라 장애물 규칙 사용**을 켠다. 내부 카메라 패널에서 모델 준비 후 **카메라 시작**을 누른다. 카메라는 후면만 사용한다. 권한 화면 이후 스캔이 중지됐으면 스캔부터 다시 시작한다.
4. **안내 시작**을 누른다. 카메라에 지원 장애물이 검출되지 않고 새 A 관측이 들어오면 접근/근접 안내를 확인한다. 미검출을 안전 확인으로 해석하지 않는다.
5. 카메라 앞의 왼쪽/오른쪽에 기둥·나무 줄기 또는 주차된 킥보드를 보여준다. 화면의 실제 bbox·class와 `시연 주의 규칙` 표시, 기존 안내가 중지된 시각, 실제 들린 방향을 기록한다. 실제 위험도는 규칙 기반이며 거리 측정은 없다.
6. 장애물이 화면에서 사라진 후 새 카메라 결과와 새 A 관측으로 접근 안내가 재개되는지 확인한다. 이어서 **카메라 중지**를 눌러 접근 안내가 중단되는지 확인한다. 카메라 복구에는 사용자의 재시작이 필요하다.
7. 카메라가 정상인 상태에서 A를 끄고 B만 남겨도 약 3초 뒤 접근 안내가 중지돼야 한다. STOP/홈 이동/카메라 실패도 각각 시험한다.

기록할 증빙: 화면의 원본 frame ID·capture_us·탐지 class/bbox·비콘 시각, `MOBI_DOOR_STATE`의 phase와 `risk=CAMERA_DEMO_CAUTION`, 이어폰에서 실제 들린 문장·방향. 상태 로그만으로 청취 성공을 표시하지 않는다. 카메라가 막히면 기존 기록 JSON 재생으로 경고 흐름을 시험하고 입력을 기록 재생으로 표시한다.
