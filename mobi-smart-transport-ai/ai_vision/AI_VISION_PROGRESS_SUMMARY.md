# AI Vision 진행 현황 및 팀 공유 자료

## 한 문장 요약

카메라 화면에서 버스를 인식하고, 화면상 위치·상대 거리·접근 여부를 판단해 안내
기능으로 전달하는 기반을 만들었다. 일반 버스를 찾는 Android용 TFLite 모델은
준비·검증됐으며, 개발 일정의 주요 레벨인 전방 장애물 탐지를 다음 우선 작업으로
전환했다.

## 완료한 작업

| 구분 | 완료 내용 | 의미 |
| --- | --- | --- |
| Android AI 기준선 | COCO 버스 모델을 Android용 `.tflite`로 변환 | 서버 없이 휴대폰 안에서 버스 탐지 가능 |
| 모델 입출력 규칙 | `640×640 RGB float32` 입력, `[1,84,8400]` 출력 해석 확정 | 앱에서 같은 규칙으로 구현 가능 |
| 버스 위치 판단 | `LEFT / CENTER / RIGHT` | 어느 방향에 버스가 있는지 전달 |
| 상대 거리 판단 | `FAR / MEDIUM / NEAR` | 화면 속 버스 크기를 기준으로 가까움 판단 |
| 움직임 판단 | `APPROACHING / STABLE / RECEDING` | 이전 프레임과 비교해 가까워지는 흐름 판단 |
| 실제 모델 검증 | 공개 버스 이미지·영상으로 TFLite 실행 | 영상에서 `CENTER/MEDIUM` → `LEFT/NEAR/APPROACHING` 전환 확인 |
| 앱 연동 문서 | Android TFLite 인계서 작성 | 카메라·권한·모델 실행을 앱에서 구현할 기준 제공 |
| 데이터셋 준비 | 라벨링 기준, 개인정보 처리, 자동 검증기 작성 | 잘못된 라벨·파일 누락을 학습 전에 검사 |
| 버스 문 데이터 확보 | 공개 데이터 1,884장 변환 | `bus`, `bus_door` 모델 학습 기반 마련 |

## 공개 버스 문 데이터셋 처리 결과

| 항목 | 결과 |
| --- | ---: |
| 전체 이미지 | 1,884장 |
| 학습 / 검증 / 테스트 | 1,507 / 188 / 189장 |
| 유지한 `bus`·`bus_door` 라벨 | 4,459개 |
| 제거한 `Number` 라벨 | 576개 |
| 데이터셋 형식 검사 | 오류 0개 |

원본의 `Front_door`, `Rear_door`는 프로젝트의 단일 `bus_door` 클래스로 합쳤고,
`Number`는 안내 기능과 무관하므로 제외했다.

## 현재 우선 작업

개발 일정의 주요 레벨인 `obstacle`을 먼저 구현한다. 이 클래스는 보행 동선을 막는
가로등·표지판 기둥·가로수 보호대·공사 가림막·불법 주정차 차량 등을 뜻하며, 사람과
자전거 같은 동적 객체는 포함하지 않는다. 따라서 일반 COCO 모델의 `person`·`bicycle`
결과를 장애물로 바꾸지 않고, 국내 보행 환경에서 직접 수집·라벨링한 데이터로
학습한다.

버스 문 모델은 공개 데이터 학습을 4회차까지 진행한 체크포인트를 보존한 뒤 보류했다.
장애물 기준선을 검증한 다음 다시 이어서 학습한다.

## 남은 개발 일정

1. 전방 장애물(`obstacle`) 데이터 수집·라벨링·학습
2. `bus_door` 모델 학습 완료, 정확도·오탐 검증, TFLite 변환
3. `bus_stop`, 점자블록, 차도·보도 등 7개 프로젝트 클래스 확장
4. Context·Audio 모듈과 실제 안내 이벤트 통합 검증
5. Android 실기기에서 카메라 입력과 모델 결과 비교
6. 실제 정류장에서 낮·밤·거리·흔들림 조건으로 신뢰도 임계값과 프레임 간격 조정

## 다른 개발자에게 전달할 내용

> 일반 버스를 찾는 Android용 TFLite 모델이 준비되어 있으며, 카메라 프레임에서
> 버스의 방향·화면상 거리·접근 여부를 `LEFT`, `NEAR`, `APPROACHING` 같은 안내
> 후보로 반환할 수 있습니다.
>
> 앱에서는 `ANDROID_TFLITE_HANDOFF.md`에 따라 카메라 프레임을 640×640 RGB
> float32 형식으로 바꿔 TFLite 모델에 넣고, 결과를 화면 또는 안내 흐름에 연결하면
> 됩니다.
>
> Context·Audio 쪽에서는 AI가 보내는 방향·거리·접근 상태를 받아 실제 음성 문구,
> 공간음향, 중복 안내 방지 규칙을 적용하면 됩니다.
>
> 버스 문 모델은 공개 데이터 1,884장을 바탕으로 학습 체크포인트까지 확보했지만,
> 현재는 일정상 우선인 전방 장애물 탐지를 먼저 진행합니다. 장애물·점자블록 등
> 안전 기능은 국내 보행 환경 데이터를 직접 확보한 뒤 확장합니다.
