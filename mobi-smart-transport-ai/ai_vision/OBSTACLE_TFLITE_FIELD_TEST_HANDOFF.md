# 장애물 TFLite 현장 검증 인계서

> 이 문서는 개별 모델의 과거 검증 기록이다. 새 Android 현장 검증은
> [통합 모델 현장 검증 인계서](UNIFIED_MODEL_FIELD_TEST_HANDOFF.md)의 단일 모델을
> 사용한다. 아래 두 모델은 비교·재현 목적으로만 보관한다.

이 문서는 실제 Android 카메라에서 전동 킥보드, 보도 기둥, 나무 줄기 감지 성능을
확인하기 위한 개별 모델 사용 규칙이다. 두 모델은 **현장 검증용 후보**다.

## 1. 전달 모델

| 모델 | 파일 | 탐지 클래스 순서 | 출력 tensor |
| --- | --- | --- | --- |
| 전동 킥보드 파일럿 | `ai_vision/models/yolo11n_parked_pm_pilot_v1_float32.tflite` | `0: bus_stop`, `1: sidewalk_pole`, `2: tree_trunk`, `3: parked_pm` | `float32 [1, 8, 8400]` |
| 기둥·나무 통합 | `ai_vision/models/yolo11n_sidewalk_pole_tree_v1_float32.tflite` | `0: pole`, `1: tree_trunk` | `float32 [1, 6, 8400]` |

두 파일 모두 입력은 `float32 [1, 640, 640, 3]` RGB이며, 각 픽셀값은 `0.0~1.0`으로
정규화한다. 원본 프레임은 비율을 유지해 640×640으로 letterbox 처리하고, 출력 박스는
여백을 제거해 원본 카메라 좌표로 되돌린다.

## 2. 출력 해석

두 모델 모두 채널 `0~3`은 정규화된 `cx, cy, w, h`이고, 이후 채널은 위 표의 클래스
순서에 따른 신뢰도다. 같은 클래스끼리 NMS를 적용한다. 시작값으로 신뢰도 `0.50`, NMS
IoU `0.45`를 사용하되, 현장 결과를 보며 조정한다.

`parked_pm`만이 전동 킥보드 안내의 대상이다. 같은 파일에 함께 들어 있는 `bus_stop`,
`sidewalk_pole`, `tree_trunk`는 초기 파일럿 학습의 부수 클래스이므로, 기둥·나무 검증은
국내 보행 데이터로 학습한 두 번째 모델의 `pole`, `tree_trunk` 결과를 기준으로 기록한다.

한 프레임에 두 모델을 모두 실행할 수는 있지만, 초기 현장 검증에서는 성능 기록을
분리하기 위해 차례로 실행하는 것을 권장한다. 실시간 안내는 검증 후 필요한 결과만
선택해 합친다.

## 3. 현장 검증 기록

Android 후면 카메라로 실제 정류장·보도에서 아래 조건을 포함해 촬영한다.

- 낮·밤·역광·흐림, 가까움·중간·먼 거리, 가림·흔들림
- 세워진 전동 킥보드와 쓰러진 전동 킥보드
- 버스 표지판·가로등·신호등 등 보도 기둥, 실제 나무 줄기
- 대상이 없는 보도 장면도 포함해 오탐 여부 확인

각 탐지에 대해 `검출`, `놓침`, `오탐`, `박스 위치 오류` 중 하나를 남긴다. 같은 영상의
연속 프레임은 모두 학습에 넣지 않으며, 촬영 시퀀스 약 20%는 이후 최종 현장 평가용으로
보관한다.

## 4. 다음 단계

현장에서 모은 놓침·오탐 장면만 라벨링하고, 기존 학습 데이터 일부와 섞어
fine-tuning한다. 현장 평가가 끝나기 전에는 이 모델의 탐지 결과를 보조 화면 표시나
기록 용도로 사용하며, 자동 음성 경고의 최종 기준으로 고정하지 않는다.
