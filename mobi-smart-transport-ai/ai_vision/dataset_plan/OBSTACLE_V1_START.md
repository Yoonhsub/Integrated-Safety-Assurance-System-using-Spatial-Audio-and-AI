# 장애물 탐지 V1 시작 안내

## 목표

개발 일정의 주요 레벨인 전방 `obstacle`을 먼저 검증한다. 이 단계는 7개 클래스를
한 번에 학습하지 않고, **장애물 하나만** 찾는 작은 모델로 시작한다. 모델이 `obstacle`
이라고 판단한 결과는 이후 AI Vision 어댑터에서 프로젝트의 `obstacle` 계약으로 전달한다.

## 무엇을 찍고 라벨링하나

포함 대상은 보행 동선을 실제로 막거나 충돌 위험을 만드는 고정·반고정 물체다.

- 가로등·표지판 기둥, 볼라드, 가로수 보호대
- 공사 콘·가림막·임시 시설물
- 보도 위를 막는 불법 주정차 차량

제외 대상은 사람, 자전거, 오토바이처럼 움직이는 객체다. 이들은 이 프로젝트의
`obstacle` 정의와 다르고, 사람 얼굴·차량 번호판은 반드시 블러 처리한다.

## 이번 시범 수집 목표

처음에는 사진 **100장**, 장애물 bbox **50개 이상**이면 충분하다. 같은 장면을 연속으로
찍었다면 한 분할에만 넣는다.

| 분할 | 사진 목표 | 용도 |
| --- | ---: | --- |
| `train` | 70장 | 모델 학습 |
| `val` | 15장 | 학습 중 성능 확인 |
| `test` | 15장 | 마지막 성능 확인 |

낮·흐림·역광, 가까움·중간 거리, 왼쪽·가운데·오른쪽 위치를 섞는다. 장애물이 없는
보도 사진도 10장 정도 포함해, 아무것도 없을 때 불필요하게 안내하지 않도록 한다.

## 폴더와 라벨 형식

원본 사진과 라벨은 GitHub에 올리지 않고 아래 로컬 폴더에 둔다.

```text
ai_vision/datasets/obstacle_v1/
├── train/images/   ├── train/labels/
├── val/images/     ├── val/labels/
└── test/images/    └── test/labels/
```

이 모델은 장애물 하나만 찾으므로 모든 YOLO 라벨의 첫 숫자는 `0`이다.

```text
0 <x_center> <y_center> <width> <height>
```

예: 사진 가운데에 있는 장애물 하나는 `0 0.50 0.55 0.20 0.40`처럼 작성한다.
자세한 bbox 경계 규칙은 [labeling_standards.md](labeling_standards.md)의 `obstacle`
항목을 따른다.

## 학습 전 확인

사진을 넣고 라벨링을 마치면 아래 명령을 실행한다. 이 명령은 장애물 전용 모델이
한 클래스(`0`)만 사용했는지와 사진·라벨 짝이 맞는지를 검사한다.

```powershell
python ai_vision/pipelines/validate_yolo_dataset.py `
  --dataset-root ai_vision/datasets/obstacle_v1 `
  --class-count 1
```

오류가 0개여야 다음 단계인 YOLO 학습으로 넘어간다.
