# 통합 비전 모델 현장 검증 인계서

## 지금 사용할 모델

Android 앱의 현장 검증에는 아래 **한 파일만** 사용한다.

`ai_vision/models/yolo11n_unified_bus_obstacle_stop_v1_float32.tflite`

모델은 한 카메라 프레임에서 다음 여섯 대상을 함께 찾는다.

| 출력 채널 | 클래스 | 현장 기록 대상 |
| ---: | --- | --- |
| 4 | `bus` | 버스 |
| 5 | `bus_door` | 버스 문 |
| 6 | `parked_pm` | 멈춰 있거나 방치된 전동 킥보드 |
| 7 | `pole` | 버스 표지판·가로등·신호등 등 보도 기둥 |
| 8 | `tree_trunk` | 보도 가까이의 나무 줄기 |
| 9 | `bus_stop` | 쉘터·벤치가 있는 버스 또는 택시 정류장 후보 |

채널 `0~3`은 각각 정규화된 `cx`, `cy`, `w`, `h`다. 입력은 RGB float32
`[1, 640, 640, 3]`이고 픽셀값은 `0.0~1.0`이다. 출력은 float32
`[1, 10, 8400]`이다. 화면 비율을 유지한 letterbox(여백 114)를 적용하고, 결과 박스는
반드시 원래 카메라 좌표로 복원한다. 시작값은 신뢰도 `0.50`, 같은 클래스끼리 NMS IoU
`0.45`다. `bus` 안에 `bus_door`가 들어가는 것은 정상이라 서로 다른 클래스끼리 NMS하면 안 된다.

## 내부 평가 결과

기존 버스 문, 전동 킥보드, 국내 인도보행 기둥·나무·정류장 데이터를 클래스 이름만 통일해 합쳤다.
원본의 학습·검증·테스트 구분은 유지했으며, 기둥·나무는 비슷한 영상 프레임이 섞이지 않도록
촬영 XML 시퀀스 단위로 분리된 데이터를 사용했다.

| 구분 | 이미지 수 |
| --- | ---: |
| 학습 | 9,765 |
| 검증 | 2,113 |
| 학습에 쓰지 않은 테스트 | 2,450 |
| 합계 | 14,328 |

학습에 쓰지 않은 테스트 분할의 결과는 다음과 같다. 이것은 실제 휴대폰 현장 성능이 아니라
각 원본 데이터 내부 테스트 결과이므로, 안전 안내의 최종 보증 수치가 아니다.

| 클래스 | Precision | Recall | mAP50 | mAP50-95 |
| --- | ---: | ---: | ---: | ---: |
| 전체 | 0.832 | 0.756 | 0.820 | 0.608 |
| `bus` | 0.993 | 1.000 | 0.995 | 0.957 |
| `bus_door` | 0.975 | 0.965 | 0.991 | 0.817 |
| `parked_pm` | 0.813 | 0.841 | 0.887 | 0.684 |
| `pole` | 0.787 | 0.720 | 0.819 | 0.532 |
| `tree_trunk` | 0.834 | 0.590 | 0.759 | 0.420 |
| `bus_stop` | 0.591 | 0.418 | 0.466 | 0.235 |

`bus_stop`의 mAP50은 0.466, 재현율은 0.418이므로 아직 정류장 여부를 단정하는 기능으로
쓰면 안 된다. 이 데이터의 `stop`은 쉘터·벤치가 있는 버스·택시 정류장만 포함하고 표지판만
있는 정류장은 제외된다. 따라서 현장에서는 화면 표시와 기록으로 먼저 확인하고, 정류장
표지판·다양한 쉘터 장면을 따로 모아 보강한다. `tree_trunk`도 재현율 0.590으로 놓침 장면
수집이 필요하다.

## Android 현장 검증 방법

1. 앱 assets에 위 TFLite 파일 하나를 넣고 후면 카메라 프레임을 전달한다.
2. 카메라 프레임을 모두 처리하지 말고, 추론 중에는 이전 프레임을 버리고 최신 프레임만 유지한다.
3. 정류장과 보도에서 낮·밤·역광·흐림·가림·흔들림·가까움·원거리를 포함해 촬영한다.
4. 각 대상에 `검출`, `놓침`, `오탐`, `박스 위치 오류` 중 하나를 기록한다. 대상이 없는 장면도
   포함해 오탐을 확인한다.
5. 같은 동영상의 연속 프레임을 모두 학습 데이터로 쓰지 않는다. 촬영 시퀀스 약 20%는 이후
   현장 평가용으로 남긴다.

## 이후 fine-tuning 원칙

앞으로 새 학습은 이 통합 모델을 기준으로 진행한다. 현장에서 모은 실패 장면을 라벨링해
기존 14,328장 데이터의 **학습 분할**과 함께 사용하고,
`yolo11n_unified_bus_obstacle_stop_v1.pt`를 시작 가중치로 fine-tuning한다. 과거의 개별
킥보드·기둥·나무 모델을 따로 이어 학습하지 않는다. 단, 현장 평가로 남긴 20%와 기존 테스트
분할은 학습에 넣지 않아 실제 개선 여부를 확인하는 데 사용한다.

재현용 통합 데이터셋 생성 도구는 다음과 같다. 원본 데이터는 `.tool-tmp`에만 두며 Git에
올리지 않는다.

```powershell
python ai_vision/pipelines/prepare_unified_field_model_dataset.py `
  --output .tool-tmp/unified_bus_obstacle_stop_v1
```

개별 모델은 비교와 원인 분석을 위한 기준선으로 보관한다. 앱의 현재 현장 검증 경로는
통합 모델 하나로 고정한다.
