# 국내 보행 기둥·나무 모델 결과 및 보완 계획

## 1. 목적과 현재 위치

이 모델은 보행자의 전방에 있는 `pole`과 `tree_trunk`를 찾기 위한 연구용
YOLO11n 모델이다. 국내 AI Hub 인도보행 사진으로 학습했으며, 실제 정류장·보도·휴대폰
카메라에서의 감지 성능은 아직 검증하지 않았다. 따라서 현재 모델은 **현장 검증용
후보 모델**이며, 음성 안내 기능에 바로 확정하지 않는다.

## 2. 학습 데이터와 누수 방지

| 항목 | 값 |
| --- | ---: |
| 원본 | AI Hub 인도보행 `Bbox_10_new` |
| 전체 이미지 | 11,781장 |
| `pole` BBOX | 12,458개 |
| `tree_trunk` BBOX | 14,736개 |
| 학습 / 검증 / 테스트 | 7,794 / 1,794 / 2,193장 |
| 학습 모델 | YOLO11n 사전학습 모델 |
| 학습 횟수 | 20 epochs |

원본은 보행 영상을 프레임 사진으로 나눈 형태다. 같은 촬영 장면의 이웃 프레임이 학습과
평가에 섞이면 점수가 부풀려질 수 있으므로 XML 한 파일(촬영 시퀀스)을 하나의 분할에만
넣었다. 변환 도구는 `pipelines/prepare_aihub_sidewalk_obstacle_dataset.py`에 있다.

## 3. 최종 수치

### 3.1 검증 분할

| 클래스 | Precision | Recall | mAP50 | mAP50-95 |
| --- | ---: | ---: | ---: | ---: |
| 전체 | 0.727 | 0.759 | 0.802 | 0.495 |
| `pole` | 0.682 | 0.798 | 0.792 | 0.512 |
| `tree_trunk` | 0.771 | 0.721 | 0.810 | 0.478 |

### 3.2 학습에 사용하지 않은 독립 테스트 분할

| 항목 | 값 |
| --- | ---: |
| Precision | 0.723 |
| Recall | 0.717 |
| mAP50 | 0.766 |
| mAP50-95 | 0.445 |

`mAP50`은 객체를 찾았는지를 비교적 느슨하게 보는 지표이며, `mAP50-95`는 박스의
경계 위치까지 더 엄격하게 보는 평균 지표다. 따라서 이 모델은 기둥·나무의 존재와
대략적 위치를 찾는 후보로는 의미가 있지만, 박스 크기만으로 정확한 사용자 거리까지
안내할 수준으로 판단하지 않는다.

## 5. 현장 검증 방법

### 5.1 촬영과 분리

1. Android 후면 카메라로 실제 버스 정류장·보도를 촬영한다.
2. 낮·밤·역광·흐림, 가까움·중간·먼 거리, 가림·흔들림 장면을 섞는다.
3. 같은 영상의 연속 프레임을 섞지 않고, 촬영 시퀀스 약 20%를 최종 현장 테스트용으로
   따로 보관한다.
4. 나머지 장면만 fine-tuning 후보로 사용한다.

### 5.2 기록할 실패 유형

| 유형 | 의미 | 보완 데이터 |
| --- | --- | --- |
| 놓침 | 실제 기둥·나무가 있지만 검출하지 못함 | 해당 객체 bbox를 라벨링 |
| 오탐 | 다른 물체를 기둥·나무로 검출함 | 객체가 없는 장면 또는 실제 다른 객체를 포함 |
| 위치 오류 | 검출은 했지만 박스가 심하게 어긋남 | 객체 경계를 정확히 다시 라벨링 |

## 6. Fine-tuning 원칙

1. 새 현장 사진만으로 재학습하지 않는다. 기존 AI Hub 데이터 일부와 현장 실패 장면을
   함께 섞어 기존 보행 환경 인식 능력이 사라지는 것을 막는다.
2. `pole`과 `tree_trunk`의 수가 한쪽으로 크게 치우치지 않게 확인한다.
3. 오탐을 줄이려면 기둥·나무가 없는 보도 사진도 포함한다.
4. 학습 뒤에는 보관해 둔 현장 테스트 사진만으로 재평가한다. 이 사진은 학습에 넣지
   않는다.
5. 현장 테스트 결과와 안내 문구의 오탐 빈도를 함께 검토한 뒤에만 TFLite 변환 및 앱
   안내 대상 추가를 결정한다.

## 7. 킥보드와의 관계

킥보드는 이 데이터 묶음에 `scooter` 라벨이 24개뿐이므로 이 모델에 포함하지 않았다.
기존 `parked_pm` 공개 데이터 모델을 실제 국내 정류장·보도 장면에서 먼저 검증하고,
세워진 상태와 넘어진 상태의 실패 장면을 모아 별도로 fine-tuning한다. 기둥·나무와
킥보드 모델은 현장 성능을 확인하기 전까지 하나로 합치지 않는다.
